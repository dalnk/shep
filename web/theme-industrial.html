ORIGIN // WHY WE BUILT SHEP

We just want simple, reliable tools that work.

It is maddening how overcomplicated and fragile modern developer tools have become. Every tool tries to be an entire operating system, bundles hundreds of bloated features nobody asked for, forces you through web logins, and then fails at the one job it was actually supposed to do.

There simply wasn't a dedicated, fast remote control app for Gemini and autonomous agent swarms. We like Gemini. We use it daily. And we needed a clean, distraction-free way to steer our swarms alongside our own agent, _, plus other agents like Codex and Claude (as long as they aren't refusing to work).

So we built SHeP: local-first, zero telemetry, zero cloud middleware. It does exactly what it says on the tin — connects to your machine over a local bridge, keeps sessions cached with 0ms latency, and lets you prompt, inspect, and unblock your swarms from any screen you have in your pocket. Tested on real daily hardware: Nothing phones, Pixel foldables, and the Daylight Computer e-paper tablet.

SPEC // 01

Instant Warm State

Zero latency tab switching and screen rotation. Active agent logs and output remain cached in memory for instant review without blank screens.

SPEC // 02

From Nothing to Daylight

Clean contrast across screen types: dark minimalism for OLED phones, zero-ghosting monochrome on the Daylight Computer, and compact glanceable layouts.

SPEC // 03

Foldable Dual-Pane Architecture

Adaptive master-detail layouts. Monitor active swarm progress in the left panel while controlling live interactive terminals on the right.

SPEC // 04

Danger Level Autonomy

Switch between 0 Danger (strict interactive confirmation) and Dangermaxxing (autonomous auto-approval on trusted agent workflows).

SUBSYSTEM // UPSTREAM

Built on herdr.dev Core

Shep connects to the herdr.dev ecosystem. It interfaces with its core orchestrator and is designed to support all upcoming herdr remotes, multi-machine bridges, session multiplexing, and swarm protocol updates.
